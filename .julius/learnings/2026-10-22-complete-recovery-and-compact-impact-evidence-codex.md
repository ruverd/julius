## Decided
Honor explicit complete delivery for context.read as well as capture and graph calls. Without a budget, return the requested range in one header plus verbatim body. Preserve the original object's digest and original byte offsets; concatenate the already delivered prefix and recovered suffix before checking that digest. Explicit budgets still cap the response.
For larger change-impact reports, try a grouped index of every evidence identity and shared edge provenance before selecting partial detailed records. Keep coverage and uncertainty visible, mark detailsOmitted, and retain the exact detailed report under its handle. Optional explicit IDs preserve duplicate or nonstandard graph identities.
Compact MCP search can abbreviate single-line spans and incoming-edge labels while retaining a path on every symbol, all source matches, ranking and truncation notices.

## Tried and ruled out
A single complete suffix read alone reduced the no-hint protocol total to 81,099 across nine executions, still above the pinned upstream's 78,903. Repeated formatting also needed attention.
Sharing a file heading across many search symbols saved bytes but could hide the source path in a selective window. Keep each symbol's path instead.

## Watch out
The benchmark policy must explicitly request complete delivery during sequential recovery; this tests a documented scripted policy, not autonomous model adoption. Do not add an initial hint to the no-hint task, increase explicit budgets, omit discovery, or stop counting recovery traffic to claim an improvement.
Grouped identity indexes omit excerpts, not affected identities. If the entire index cannot fit, retain truthful omittedEvidence counts and full-detail recovery. Unknown token counts from long unbroken JSON runs must fall back safely and remain null, never zero.
