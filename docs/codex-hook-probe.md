# Opt-in Codex UserPromptSubmit probe

`julius probe codex-hook --execute` runs one synthetic Codex CLI turn and may incur model usage. The equivalent API is `julius.codex_hook_probe.probe_codex_hook(confirmed=True)`; it is never run on import. The probe uses an empty temporary working directory, a temporary executable POSIX shell hook script, and an inline `-c` hook value. It leaves user and project configuration untouched, and uses the client's ordinary authentication without copying credentials.

The hook requires `/bin/sh`, works in a standalone Julius binary without an external Python installation, and writes a temporary invocation marker and returns a synthetic `additionalContext` token. The prompt asks Codex to reply with that token without tools. The result reports `hookInvoked`, `markerObserved`, and final JSONL usage when available. It does not retain prompt text, model response text, or stderr. Unknown usage stays `null`. `accepted` means the marker file exists, the final message matches the synthetic token, and the turn completed. The command has a 30-second timeout and rejects stdout over 1 MiB or stderr over 64 KiB.

On September 21, 2026, two live synthetic turns on codex-cli 0.154.0 returned `accepted`. The first used a Python script; the second exercised the current standalone-compatible shell script. In the second turn, the hook marker file existed, Codex's final message matched the synthetic additional-context token, and the client reported 20,900 input tokens, zero cached input tokens, and 28 output tokens. This is narrow evidence that this CLI build accepted the inline `UserPromptSubmit` command hook. It does not test Julius's production hook, any tool-output rewrite, another version, or savings. The probe does not change `CODEX_HOME` or install hooks.

The hook response follows the official [Codex hooks documentation](https://developers.openai.com/codex/hooks), which documents `UserPromptSubmit` and `hookSpecificOutput.additionalContext`. The [advanced configuration reference](https://developers.openai.com/codex/config-advanced) documents inline `[hooks]` configuration structure.
