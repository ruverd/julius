# Jev shadow decision boundary

Status: experimental direct TypeSafe HTTP gateway, unverified against a live account; no benchmark result.

`julius.jev.shadow_decide` accepts an injected `JevGateway`. Normal Julius installation does not need TypeSafe credentials, a model, or network access. The explicit `julius jev shadow` CLI command and `Julius.evaluate_jev_shadow` SDK method invoke this module when called; SDK records a decision and any auxiliary usage in the local ledger. `TypeSafeGateway` uses one direct HTTPS POST to `https://api.typesafe.ai/v1/systemone`, Bearer authentication, `jev-latest`, and a Choice question. Its transport disables environment proxies and redirects, performs no retries, and caps response at 64 KiB. Python socket timeout bounds network I/O; caller's deadline also rejects responses that arrive late. An injected transport supports fixture tests.

The module uses only a Choice-shaped response for three eligible actions: `keep`, `retrieve`, and `compress`. The official TypeSafe documentation also defines Score and Noul, but neither is needed for this narrow shadow choice. An adapter may map TypeSafe's `response.answers[question_id].choice` and `.confidence` into `JevAnswer`; this repository does not claim tested compatibility with a specific SDK release.

Only allowlisted numeric and boolean metadata reaches a gateway. Raw prompts, paths, project identifiers, and secrets are excluded. Caller must pass only authorized state. A positive `max_cost_usd` allows an external call; it is **not a hard spending cap**. Actual usage and modeled cost become known after the call, so `budget_exceeded` means the already-incurred modeled cost exceeded the configured threshold. Price rates are caller supplied USD per million input/output tokens; a reported token count is not a price. Missing price yields unknown cost and a deterministic `keep` fallback; an eligible suggestion remains visible for shadow analysis, alongside provider-reported usage and actual model. Cost over budget, timeout, invalid choice, or low confidence also fall back to `keep`. All receipts keep `applied_action=keep`, including successful suggestions: shadow mode never alters a user request. Direct callers of `shadow_decide` must persist and account for its receipt; the `Julius` SDK method performs that ledger write. Production wiring needs provider-side limits or a provable upper bound plus atomic reservation and reconciliation before claiming a hard spending cap.

Confidence is a threshold on a reported value, not a calibrated success probability. Before enabling active decisions, validate live API behavior, measure cost and quality on target tasks, and add an explicit non-shadow policy gate.

Sources: [TypeSafe Introduction](https://docs.typesafe.ai/introduction), [Primitives](https://docs.typesafe.ai/primitives).
