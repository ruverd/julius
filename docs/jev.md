# Jev shadow decision boundary

Status: experimental direct TypeSafe HTTP gateway. One live Choice request with synthetic state succeeded on September 21, 2026, returning `jev-1.13.0`, 373 input tokens, 31 output tokens, `compress`, and confidence `0.77`. Dollar cost was unavailable because no price was configured. This is a protocol smoke test, not a quality benchmark or active-decision validation.

`julius.jev.shadow_decide` accepts an injected `JevGateway`. Normal Julius installation does not need TypeSafe credentials, a model, or network access. The explicit `julius jev shadow` CLI command and `Julius.evaluate_jev_shadow` SDK method invoke this module when called; SDK records a decision and any auxiliary usage in the local ledger. `TypeSafeGateway` uses one direct HTTPS POST to `https://api.typesafe.ai/v1/systemone`, Bearer authentication, `jev-latest`, and a Choice question. Its transport disables environment proxies and redirects, performs no retries, and caps response at 64 KiB. Python socket timeout bounds network I/O; caller's deadline also rejects responses that arrive late. An injected transport supports fixture tests.

The module uses only a Choice-shaped response for three eligible actions: `keep`, `retrieve`, and `compress`. The official TypeSafe documentation also defines Score and Noul, but neither is needed for this narrow shadow choice. The gateway maps TypeSafe's `response.answers[question_id].choice` and `.confidence` into `JevAnswer`. The one live response establishes compatibility for the observed `jev-1.13.0` shape, not every model or future release.

Only five metadata fields can reach a gateway. `input_tokens` and `estimated_reduction_tokens` must be exact integers from 0 through 1,000,000,000; booleans do not count as integers. `artifact_recoverable`, `has_protected_content`, and `model_local` must be exact booleans. Other keys are dropped. An invalid value under an allowed key produces `invalid_state` before any gateway call. Direct `TypeSafeGateway.choose` calls raise `ValueError` for the same invalid state. Raw prompts, paths, project identifiers, and secrets are excluded; callers should still pass only authorized state.

A positive `max_cost_usd` allows an external call; it is **not a hard spending cap**. Actual usage and modeled cost become known after the call, so `budget_exceeded` means the already-incurred modeled cost exceeded the configured threshold. Price rates are caller supplied USD per million input/output tokens; a reported token count is not a price. Missing price yields unknown cost and a deterministic `keep` fallback; an eligible suggestion remains visible for shadow analysis, alongside provider-reported usage and actual model. Cost over budget, timeout, invalid choice, or low confidence also fall back to `keep`. All receipts keep `applied_action=keep`, including successful suggestions: shadow mode never alters a user request. Direct callers of `shadow_decide` must persist and account for its receipt; the `Julius` SDK method performs that ledger write. Production wiring needs provider-side limits or a provable upper bound plus atomic reservation and reconciliation before claiming a hard spending cap.

Confidence is a threshold on a reported value, not a calibrated success probability. Before enabling active decisions, validate live API behavior, measure cost and quality on target tasks, and add an explicit non-shadow policy gate.
