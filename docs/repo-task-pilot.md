# Frozen repository task pilot

`julius.repo_task_pilot.run_repo_task_pilot` is an opt-in exploratory paired run for Claude Code. It uses a tiny, frozen note-service repository and four exact-answer tasks: bug localization and code comprehension, each in English and Portuguese. It is not a representative full coding benchmark. It measures neither edit quality nor live client compatibility from fixture tests.

The caller supplies a work directory, project ID, per-arm turn, USD, and wall-time caps, and may choose a model and frozen task IDs. Calling this function starts paid client sessions. The default is to make no model calls. The packaged `python/julius/data/repo_task_pilot.json` holds the entire repository and answer key; `tests/fixtures/repo-task-pilot/tasks.json` mirrors it for frozen-fixture checks. The CLI entry point is `julius evaluate repo-pilot` (see `--help` for limits and task selection). Before the first client call, the pilot writes `corpus-registration.json` containing SHA-256 of the exact fixture bytes and initializes a partial `report.json`.

Each task runs baseline and safe-hook arms in separate project and Julius data directories. Both launch with `--restricted`, only Bash plus the Julius recovery MCP tool visible, and a PreToolUse gate that permits one exact `cat README.md notes.py store.py routes.py` request. All other tool requests are denied. The safe arm adds Julius's existing PostToolUse hook; the baseline has no PostToolUse hook. The pilot never executes model-generated code or gives the model a network tool. The client itself may contact its provider for these explicitly requested sessions. Julius reporting remains offline.

Each arm writes raw client stdout and stderr, plus a result with completion, exact answer grade, tool evidence, model identity, latency, and client-reported usage and cost. An answer passes only when the client completes successfully, returns the exact frozen answer, makes exactly one permitted Bash request with a matching successful tool result, and makes no unexpected tool requests. Failures remain in the report, and the next arm still runs. Cost and usage are client-reported session totals, not provider measurements. A missing value stays null. The final report is descriptive; the small corpus and possible model variation do not support a broad quality claim.
