# Experimental transcript imports

Julius accepts text that a user explicitly selects for import. It does not scan client directories, read credentials, change client settings, or run a model. The importers are fixture tested only. They have not passed the live client compatibility release gate.

`importClaudeTranscript(text, { projectId, sourceId })` recognizes Claude Code JSONL assistant rows with `sessionId`, `timestamp`, `requestId`, and a nested `message` containing `id`, `model`, `usage`, and `stop_reason`. Multiple rows for the same session and message ID are treated as one API message; the latest row supplies its recorded counters. A missing final stop reason marks usage incomplete. This format and its repeated message behavior are described in [Claude Code's transcript issue](https://github.com/anthropics/claude-code/issues/90509) and [final usage issue](https://github.com/anthropics/claude-code/issues/27361). Those issues are format evidence, not compatibility certification.

`importCodexRollout(text, { projectId, sourceId })` recognizes Codex `session_meta` and `event_msg` rows whose payload type is `token_count`. It computes increments from `info.total_token_usage`, skips unchanged snapshots and the first snapshot after a counter reset, and leaves absent cache counters null. If no `session_meta` is present, the first cumulative snapshot becomes a baseline and is not imported. These increments are session deltas rather than individual requests; request, call, and model IDs remain null, and completeness is false. The canonical record shape appears in the [Codex rollout test fixture](https://github.com/openai/codex/blob/main/codex-rs/app-server/tests/common/rollout.rs). [Codex's token-count issue](https://github.com/openai/codex/issues/14489) documents repeated `last_token_usage` values, which is why Julius does not add those values.

Imported costs remain null, task IDs remain unknown, and these usage records establish no baseline or savings. The input text may contain sensitive content; callers should keep it local and discard it after import. Versions and live behaviors must be verified before claiming client support.

For Anthropic, the canonical event `inputTokens` is the sum of uncached input, cache reads, and cache writes. The original uncached count remains in the normalization result and in the raw record. If any category is absent, the canonical total is null. Cache read and write counters are subsets of this normalized input total and must not be added to it again in reports.

Repeated imports of identical text produce stable event IDs. If the same Claude message later gains final usage, importing the changed transcript is a correction to reconcile explicitly; it must not be silently counted as another call.
