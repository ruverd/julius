# Experimental Claude Code hook adapter

`julius.claude_hooks.post_tool_use` accepts a parsed Claude Code `PostToolUse` event, an explicit Julius safe policy, a local `ArtifactStore`, a project ID, and `recovery_available=True` only when the caller has verified that a model-accessible recovery tool is registered and working. It returns a JSON-compatible hook response or `None`. `julius hook claude-post-tool-use --project PROJECT --profile safe --recovery-available --data-dir STORE` reads one event from stdin and emits that response to stdout only when applicable. Without `--recovery-available`, it passes through. Julius does not install the hook or modify client settings. Tests use synthetic events and a local subprocess, so live Claude compatibility remains unverified.

The adapter only considers successful `Bash` tool responses with string `stdout` and empty `stderr`. It leaves interrupted, failed, image, unknown-shape, and other-tool results untouched. It also skips text containing protected approval, permission, failure, or warning content under Julius's optimizer policy. The default `recovery_available=False` passes through without writing an artifact. Before replacing stdout, it saves and verifies the original in a local project-scoped artifact. The replacement retains the rest of the `Bash` response and includes an artifact ID for recovery. The operator must manage artifact retention and ensure the store stays available to recover shortened results. No model call or network operation occurs.

Claude Code's [hooks reference](https://code.claude.com/docs/en/hooks#posttooluse) documents the `PostToolUse` event, its `tool_input` and structured `tool_response`, and `hookSpecificOutput.updatedToolOutput`. That field replaces the result Claude sees only after the tool has run; the replacement must match the tool's output shape. The documented `Bash` example has `stdout`, `stderr`, `interrupted`, and `isImage`. The reference also warns that telemetry records the original output and that a malformed replacement can be ignored. No guarantee about live behavior follows from these local fixture tests.

Register the recovery server for the same project and store before enabling the hook. The CLI flag is an operator attestation, not an automated client capability probe. A hook response alone is a candidate: Julius does not count it as sent-request input savings until the client request or equivalent downstream evidence confirms it was used. Malformed and oversized hook input passes through without changing tool output.
