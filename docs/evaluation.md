# Offline paired-task evaluation

`julius.evaluation.analyze_paired_trials` analyzes trial records supplied by the caller. It does not run tasks, contact models, or claim a benchmark result. Each `Trial` is one attempted task run, whether successful or failed. Its token counts, USD cost, and latency cover the full run, including retry attempts; `retries` is the number of additional attempts. Unknown measurements are `None`, never zero.

Supply one record per `(arm_id, task_id)` and name distinct baseline and candidate arms. The analyzer compares only task IDs present in both arms, lists unmatched IDs, and includes failures in every denominator. It reports totals, counts, and averages per attempt (`retries + 1`), per attempted task, and per successfully resolved task. All numerators include failed-run expenditure. Per-resolved-task averages divide the full paired-arm expenditure by successful task count and are null when there are no successes. Per-attempt averages divide aggregate usage by attempt count; they do not reconstruct the usage or success of an individual attempt. When input, cache-read, and cache-write tokens are all known, their counts must satisfy cache-read plus cache-write less than or equal to input.

Savings are baseline minus candidate for tokens, cost, and latency, so negative values remain visible. A metric is unknown if any paired run lacks that measurement. `success_delta` is candidate successes minus baseline successes. The report contains no confidence interval or causal claim; a meaningful experiment still needs controlled task selection, independent outcome grading, and repeated trials where appropriate.
