# Julius Implementation Plan

**Goal:** Deliver an executable, offline-first foundation and an explicit path to the complete Julius product.

**Architecture:** A modular Python monolith owns an append-only SQLite ledger. Rust implements performance-sensitive processing through a narrow PyO3 boundary. Pure optimization creates candidates and receipts; authorized harnesses execute requests and record usage separately.

**Tech stack:** Python, Pydantic, SQLite WAL, pytest, Rust, PyO3/Maturin, local HTML. TypeScript is optional for the dashboard and Bulma SDK.

**Execution update:** The user approved switching away from the Bun/TypeScript core on September 21, 2026. Follow `docs/plans/2026-09-21-stack-migration.md` before continuing these tasks. File paths below identify existing migration sources; their deliverables must move to the Python/Rust target layout. Existing code must be preserved until ported behavior passes verification.

**Spec:** `docs/specification.md`.

## Global constraints

All documentation is English. Unknown is null, negative savings remain signed, estimates carry evidence, and reports perform no model calls. No global client configuration changes. All test artifacts use temporary directories.

## Execution record

The primary agent integrated CLI, reporting, SDK, documentation, and build validation. Three parallel GPT-5.6 Sol workers implemented ledger/accounting, optimizer/artifacts, and adapters/importers. Follow-up subtasks added explicit pricing and snapshot-scoped lexical memory. Independent review found and corrected persistent duplicate aliases, cross-project coverage joins, cross-session cumulative counters, pre-policy content retention, immutable shared budget caps, stale reconciliation pricing provenance, unknown empty cost totals, and memory integrity/retention checks.

Tasks 1–4 are delivered for this foundation. Native client certification and the follow-on gates above remain open. The first CLI filter is a candidate generator, not automatic agent integration. Optional pricing and FTS5 modules are exposed through the SDK without claiming completed milestones C–E.
