# Offline HTML dashboard

Request coverage excludes session-delta usage even when the client supplies a request ID: one session aggregate is not evidence of one observed request. Its counters remain in usage totals.

`julius dashboard --output report.html` writes a self-contained aggregate report. It loads no external scripts, styles, fonts, or images and makes no model request. The page has a keyboard-operable table, responsive layout, light and dark color support, and local dropdown filters for dimensions present on every displayed group. The CLI passes its selected grouping, so the standard dashboard can filter model groups, or client groups with `--by client`. A caller supplying aggregate groups with explicit project, task, or strategy fields gets filters for those complete, safe dimensions. The dropdowns hide rows locally and do not recompute aggregate totals.

Unknown totals display as unavailable with a known subtotal and unknown-record count. The summary separates calls with IDs from session usage deltas, shows incomplete usage records, and displays transformed requests over observed requests with IDs. That denominator does not cover unobserved machine traffic. Signed financial values are shown as supplied, including negative savings; the dashboard does not derive a baseline, price, or savings figure. If no financial comparison was supplied, it shows unavailable. The page omits source IDs and redacts path-shaped group labels. It contains no raw prompts or event bodies. Existing report data can still contain sensitive non-path labels, so review the aggregate before sharing an exported HTML file.

The filters use inline JavaScript under a restrictive document policy and need a browser with JavaScript enabled. Without JavaScript, the full table remains readable. The page is a local view of supplied evidence, not a task-quality or provider-billing certification.

The daily UTC series groups recorded usage by event timestamp and by mutually exclusive primary, auxiliary, restoration, and unknown categories. Each category exposes input, output, cache read, and cache write separately; cache counters describe input usage and must not be added to input tokens. The JSON series also exposes auxiliary overhead (auxiliary plus restoration usage), signed direct whole-request input reduction, and tool-output reduction as separate fields. Tool-output changes can be part of a measured whole-request change, so their reductions must not be added together. A reduction belongs to its transform's UTC day and is not a financial saving. The HTML table repeats the day's reduction and incomplete-record count across its category rows for readability; those repeated cells are not additive. Missing counters retain null totals and a known subtotal. An absent event timestamp cannot be assigned a day, and unobserved traffic remains outside the series.

The task section groups observed events by `(projectId, taskId)` within the selected period. It counts all observed task IDs separately. Attempted requires usage, an outcome, or a sent transform; candidate-only transforms and decisions do not establish an attempt. Resolved requires the latest outcome event to say `resolved` exactly. It reports how many attempted tasks have an outcome, observed calls with IDs, incomplete usage records, input/output/cache counters, auxiliary record counts, direct whole-request input reduction, and tool-output reduction. Request coverage counts only sent request-scope transforms paired with an observed request ID; a tool-output transform alone cannot establish request coverage. These columns are separate: direct reduction is not a financial or output saving, and tool-output reduction cannot be added to whole-request reduction. Missing counters stay unavailable and signed reductions can be negative. The period displays its timezone and uses a half-open interval. A sent transform can evidence an attempt without an observed usage call, but the report cannot establish full traffic coverage or task quality. Task labels are aggregate identifiers; review them before sharing the file.

The task table can be filtered by outcome. A project filter appears when every project ID is a safe, non-path identifier. Wide task details stay within a horizontally scrollable, keyboard-focusable region with a visible focus outline; arrow keys can move through columns. The live row count reports the visible tasks. “Export visible tasks as CSV” downloads only the currently visible rows, with the table headings and displayed unknown-value text. It runs entirely in the page, makes no network request, and guards spreadsheet formula-like text. Negative numeric values remain signed. Without JavaScript, the full task table remains readable.

Optional browser acceptance: `uv run --with playwright python scripts/browser_dashboard_smoke.py --browser-executable /path/to/chrome`. The script builds a synthetic two-task report and checks model/outcome filters, visible-row CSV, keyboard horizontal scrolling, and light/dark rendering. It does not need a network listener or a model. Passing this smoke does not establish full accessibility or cross-browser compatibility.

Each task also reports call cost in USD by provenance. `callCostUsd` includes at most one recorded amount per usage record, whether it came from provider usage, a client estimate, or a price model. `costSources` lists those bases and includes `unknown` when a record lacks cost. This mixed total is not a verified invoice or a financial saving; an unknown cost leaves its total unavailable with a known subtotal. `modeledCostUsd` includes client-reported estimates and price-modeled costs; `clientEstimatedCostUsd` and `priceModeledCostUsd` partition that subtotal. `providerChargedUsd` is separate from modeled cost. These columns are views of the same call records and must not be added to `callCostUsd`. `costByCategory.primary` and `costByCategory.auxiliary` partition each basis by usage category; auxiliary includes restoration and any non-primary category. A task with no usage has unavailable costs. The task table and its visible-row CSV include these cost columns and preserve signed amounts.
