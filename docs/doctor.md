# Doctor capability matrix

`julius doctor` reads the local Claude Code and Codex CLI version strings and runs a bounded, offline subprocess check of Julius's own Claude hook and MCP recovery server. It does not invoke either client, send a model request, inspect credentials, or modify client configuration. The local probe result is separate from each client's historical adapter capability manifest.

`adapterCapabilities` follows the versioned Julius adapter contract: adapter and exact client versions, status (`tested`, `experimental`, `observe_only`, or `unsupported`), observation/replacement/routing/attribution/approval booleans, and verified protocol versions. It is a declaration of narrow evidence on an exact client version, not a test of the client during this `doctor` invocation. `featureStatus` is a parallel, narrower status view for the same historical integration evidence; neither field means the current client passed a live test. `localProtocolProbe` is the only subprocess test in this command, and it starts Julius, not the client. An unknown or differently formatted version receives `unsupported` with every capability false. Empty `supportedProtocolVersions` means Julius has not certified a versioned wire protocol.

The older `capabilities` field remains for callers that read it. Its flags describe only what this `doctor` invocation verified against a client, so they remain false; `capabilitiesScope` makes that limit explicit. Do not merge it with `adapterCapabilities` or treat an offline local probe as live client evidence.

For Claude Code 2.1.278, bounded [live synthetic probes](live-claude-validation.md) observed a session usage delta, an actual model in a print result, a Bash `PostToolUse` output replacement, and task attribution through the launcher. The manifest is `experimental`; it does not claim complete request observation, routing, general tool coverage, or approval-flow preservation. For Codex CLI 0.154.0, one [live synthetic JSONL probe](codex-live-probe.md) observed session usage with caller-supplied task identity. The manifest is `observe_only`; it does not claim output replacement or actual-model attribution. Those historical probes do not certify the current installation or newer client versions.

The model and runtime scans are separate explicit read-only commands. `doctor` cannot certify a loaded local model, xAI compatibility, sent-request reduction, output savings, or task quality.
