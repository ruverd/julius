# xAI Responses adapter

Status: fixture tested, experimental. Live xAI compatibility and any savings remain unverified.

`XAIAdapter.prepare(request)` validates and serializes a complete Responses API request without network activity. `send_once(request, api_key, transport=None)` sends one explicit POST to `https://api.x.ai/v1/responses` when called. Caller must supply a dedicated, authorized xAI API key and an explicit model. The adapter does not select a model, compress content, route from another client, retry, follow redirects, or run client-side tool calls. It disables environment proxies. If an explicit request includes xAI server-side tools, xAI may execute those tools as part of that one authorized request; caller must review and authorize those effects before dispatch. Request fields, including system instructions, function outputs, tool IDs, and cache keys, pass through unchanged.

Result separates requested alias from response model. Input, output, cached input, reasoning, and total tokens come only from the provider's `usage` object. Cached input is included within input; reasoning is included within output. Both documented `input_tokens`/`output_tokens` and `prompt_tokens`/`completion_tokens` shapes are accepted without adding aliases. Conflicting aliases make the receipt incomplete. Provider-billed `cost_in_usd_ticks` is retained as an optional integer (1 USD = 10^10 ticks); it includes server-side tool costs and must not be added to them again. Missing values stay unknown. Transport failure, missing actual model or response ID, missing usage, and unfinished responses remain incomplete; no zero usage or baseline is invented. `raw_usage` retains provider counters for later versioned normalization. `raw_response` can contain sensitive content and should follow artifact retention rules if persisted.

xAI documents `store=true` by default and 30-day stateful response retention. The adapter preserves the caller's `store` choice and does not silently change it. Setting `store=false` does not by itself establish zero data retention; xAI documents separate account-level data-retention behavior. Current adapter does not reduce generated output tokens. Julius can record actual output use, but savings in output require a comparable baseline or controlled experiment. Fixture tests prove request preservation and counter parsing only.

Primary references: [xAI Responses API](https://docs.x.ai/developers/rest-api-reference/inference/responses), [xAI prompt cache usage](https://docs.x.ai/developers/advanced-api-usage/prompt-caching/usage-and-pricing), [xAI cost tracking](https://docs.x.ai/developers/cost-tracking), [xAI data retention](https://docs.x.ai/developers/faq/security).
